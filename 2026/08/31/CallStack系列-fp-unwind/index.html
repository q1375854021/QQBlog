CallStack 学习系列 —— Frame Pointer Unwind

本篇是 CallStack 学习系列的 Frame Pointer（帧指针）unwind 部分。
配套代码：src/FP_Unwind/fp_unwind.c。

0. 两个核心问题

整个 CallStack 学习，归根结底是回答两个问题：

  1. 如何拿到当前的 IP/RIP，并据此一路 unwind 出完整的调用栈；
  2. 如何把 unwind 出来的地址解析成「函数名 + 源码位置」（symbol/source 解析）。

本文先用最简单、最常用的 Frame Pointer 方法把这两件事打通。

1. Callstack 方法一览

方法 核心机制 准确性 开销 对程序要求 推荐程度
Frame Pointer RBP 链 高 低 编译时保留 FP ⭐⭐⭐⭐⭐
DWARF CFI .eh_frame / .debug_frame 很高 高 编译器生成 unwind info ⭐⭐⭐⭐
ORC Linux ORC unwind 很高 低~中 主要用于 kernel ⭐⭐⭐

perf 帮你做 kernel + unwind 取决于 取决于 最简单 ⭐⭐⭐⭐⭐

2. Frame Pointer 原理

Frame Pointer 的核心思想：每个函数栈帧里都保存着「上一个栈帧的 FP」和「返回地址」，
于是从当前函数一路顺着 RBP 链往上，就能找到所有 caller。

2.2 经典 prologue / epilogue

拿一个最小例子看编译器生成的汇编：

  • prologue：push %rbp; mov %rsp, %rbp
  • epilogue：pop %rbp; ret（等价于 leave; ret）

-O0 下 x86-64 默认保留 frame pointer；但开了优化后编译器可能省略它
（-fomit-frame-pointer），此时要用 -fno-omit-frame-pointer 强制保留，否则 FP unwind 会失效。

3. 动手实验：fp_unwind.c

3.1 编译

两个 flag 都很关键：

flag 作用
-fno-omit-frame-pointer 强制每个函数都保留 rbp 作为 frame pointer，保证 RBP 链完整
-rdynamic 把程序自己的全局符号导出到动态符号表 .dynsym，dladdr 才能解析出函数名

注意：不加 -rdynamic 程序也能跑，但 dladdr 找不到 baz/bar/foo/main，
每个帧只会输出 ???。因为普通链接不会把这些函数放进 .dynsym。

3.3 逐段讲解

  1. **symbolize(ip)**：用 dladdr 做 symbol 解析（对应开头的「问题 2」）。
    info.dli_saddr 是符号的起始地址，ip - dli_saddr 就是符号内偏移，
    最终打印成 符号名+0x偏移 (文件)。

  2. **get_stack_range()**：unwind 前先拿到主线程栈的 [low, high) 范围，
    用来做边界检查，避免顺着 rbp 读到非法内存。来源是 /proc/self/maps 里的 [stack] 行。

  3. **unwind_fp()**：核心循环。每一步先打印并符号化当前 rip，再做三层安全检查，
    然后 rbp = next_rbp; rip = next_rip 进入上一帧。

  4. baz() 里取 rbp / rip 的内联汇编：

    • mov %%rbp, %0：把当前 rbp 存到变量；
    • leaq 0(%%rip), %0：RIP 相对寻址、偏移为 0，得到下一条指令的地址，即「当前 IP」。

  5. **noinline**：保证 baz/bar/foo 都是真实的 call 调用、有真实栈帧，
    不会被编译器内联掉而破坏调用链。

3.4 运行结果解读

  • #0 是 baz 内部取的「当前 IP」，所以偏移是 baz+0x1a；
  • #1 ~ #3 是依次从 [rbp+8] 读到的返回地址，分别落在 bar/foo/main 内；
  • 最后走到 main 的上一帧（__libc_start_main 那一层）时 next_rbp <= rbp 成立，
    循环结束，打印 next_rbp <= rbp。

4. 关键点 & 易错点

  1. 必须保留 frame pointer。优化编译会省略 rbp（-fomit-frame-pointer），
    此时 [rbp]/[rbp+8] 不再是「saved rbp / return addr」，unwind 会走飞。
    所以要么用 -O0，要么显式加 -fno-omit-frame-pointer。

  2. 必须做边界检查。rbp 链一旦损坏（或走到没 frame pointer 的库函数），
    会读到野指针。所以要限定 rbp 在 [stack_low, stack_high) 内，并保证帧链单调递增。

  3. **符号化依赖 -rdynamic**。dladdr 查的是动态符号表 .dynsym，
    程序自己未导出的普通函数（baz/bar/foo/main）默认不在里面，必须用 -rdynamic 导出。

  4. offset 用「符号起始地址」算：ip - info.dli_saddr，不是减去函数调用处地址。

  5. 帧 0 与后续帧的 ip 来源不同：帧 0 是 baz 里用 leaq 0(%%rip) 抓的「当前指令」，
    后续帧是从 [rbp+8] 读出的「返回地址」。

5. 参照资料：栈帧的 push / pop 细节

下面用一个更通用的例子，把 call / ret 期间栈的变化一步步拆开。

当 main 调用 foo 时（x86-64 栈向下增长）：

  1. call foo：rsp -= 8; *(uintptr_t *)rsp = rip_next; rip = foo
    （即先把返回地址压栈，再跳转到 foo）。

  2. push rbp（foo 的 prologue 第一步）：rsp -= 8; *(uintptr_t *)rsp = rbp
    （保存 caller 的 rbp）。

  3. mov rsp, rbp（foo 的 prologue 第二步）：rbp = rsp
    （从这里开始，才算 foo 真正的栈帧，之后局部变量都靠 rbp 偏移寻址）。

  4. sub rsp, N：一次性分配整个局部变量区。

  5. ret（foo 的 epilogue）：先 pop rbp（rbp = *(uintptr_t *)rsp; rsp += 8），
    再 ret（rip = *(uintptr_t *)rsp; rsp += 8，跳转回 caller）。

总结成一句话：

  • call 的等价动作：push rip; jmp foo; push rbp; rbp = rsp
  • ret 的等价动作：pop rbp; pop rip; jmp rip

为什么 push / pop 能这样镜像？因为函数内局部变量都是通过 rbp 偏移寻址，
rsp 基本一直停在 push rbp 之后的位置，只在 push/pop 时短暂移动。

几个关键概念：

  1. RSP（stack pointer）：始终指向栈顶。push 是 rsp -= 8; *rsp = val；
    pop 是 val = *rsp; rsp += 8。

  2. RBP（base pointer）：栈帧的基准点。编译器用 [rbp-8]、[rbp-16] 访问局部变量；
    用 [rbp+8]、[rbp+16] 访问 caller 栈帧里的数据（如返回地址、caller 的 rbp）。

  3. call foo：保存 caller 的返回地址（rsp -= 8; *rsp = 下一条指令地址），然后跳转到 foo。

  4. 进入 foo 前：先 push rbp，再 rbp = rsp。

  5. RIP（instruction pointer）：取指完成后 IP 指向下一条指令的地址，
    因此可以把它理解为「下一条待执行指令的地址」。

  6. 局部变量区：直接 sub rsp, N 划出来，局部变量通过 rbp ± 偏移 寻址。
