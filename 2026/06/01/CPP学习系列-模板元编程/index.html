3. 模板基础

3.1 模板的本质

模板本质上就是编译器宏，核心机制是实例化与代码膨胀。模板在编译之前，在物理上是不存在的，它不占据任何代码段（.text）的内存。

模板只是你给编译器下达的一套指令，告诉编译器：如果以后有人需要某种类型的函数/类，你就照着这个模子给我当场打印一份出来。

3.2 什么是 AST

AST 的全称是 Abstract Syntax Tree（抽象语法树）。在编译器（如 GCC、Clang）的眼中，你写的 C++ 代码是一棵倒挂的树。

编译器处理代码的阶段：

**词法分析 (Lexical Analysis)**：把字符切成一个个单词（Token）

**语法分析 (Syntax Analysis)**：把这些 Token 组装成一棵 AST，只保留代码的纯粹逻辑结构

3.6 延迟实例化

延迟实例化（Lazy Instantiation）是指：当你实例化一个类模板时，编译器只生成你实际调用的成员函数的代码。

必须立刻实例化的元素：

  • 普通成员变量：T data（因为需要确定内存布局）
  • 父类：继承自 Base<T>（因为子类需要在父类后面布局）

可以延迟实例化的元素：

  • 静态成员变量（不影响 sizeof）
  • 嵌套类/内部类型（只是”概念”，不占内存）
  • 成员函数（没调用就不生成）
  • 虚函数除外（需要生成虚表）

5. SFINAE：替换失败不是错误

5.1 SFINAE 的核心原理

SFINAE：Substitution Failure Is Not An Error

翻译成中文就是：替换失败不是错误。

这是 C++ 模板元编程中最核心的底层机制之一。当编译器尝试实例化一个函数模板时，如果模板参数替换过程中出现了失败，编译器不会报错，而是默默跳过这个候选函数，继续寻找其他匹配的函数。

如果 T 没有某个成员，这里就会出现 substitution failure，编译器会忽略这个函数模板，继续寻找其他匹配的函数模板。如果还找不到其他的，那么就会编译报错了。

5.3 SFINAE 代码示例

  2. test<WithoutType>(0)：第一个模板替换失败（WithoutType 没有 type），SFINAE 机制生效，跳过第一个，匹配第二个

8. CRTP：奇特递归模板模式

8.1 问题背景

在 C++ 中，基类的成员函数默认无法调用派生类的特有函数（除非使用虚函数）。但虚函数有运行时开销（虚表查找、间接调用）。

CRTP 的基类，编译期静态分发。在不适用虚函数的前提下，让基类能够调用到派生类的特有函数。

8.2 CRTP 的基本模式

8.3 static_cast 向上转型的原理

  • this 的类型是 Animal<Derived>*
  • static_cast<Derived*>(this) 将基类指针转换为派生类指针
  • 此时调用 ->do_speak()，就会调用到实际对象类型的成员函数

8.4 构造顺序详解

构造顺序是这样的：

第一阶段：声明了 Cat，但是这个 Cat 是个空的，只有一个声明而已。没必要立刻实例化。

第二阶段：发现基类是一个模板，并且模板的参数是 Cat。

第三阶段：开始实例化 Animal。编译期将 Animal 模板里的 Derived 替换成 Cat。

第四阶段：不需要实例化 Cat，因为 Animal 里并没有用到 Cat 的成员函数，只是用到了 Cat 指针而已。

第五阶段：回到 Cat，然后编译内部的 do_speak()，至此 Cat 变成一个完整类型。

灵活性 低（必须知道派生类型） 高（运行时多态）
虚表 不需要 需要

14. C++20 requires：编译期审查机制

14.1 requires 的核心作用

requires 关键字的核心作用就是：给模板参数（类型或数值）设立”编译期审查机制”。

requires 就像一个大闸门或者安检仪，只有符合特定语法或语义规则的类型，才能顺利通过编译。

requires 拥有两重完全不同的身份（作用）：一个是用来”限制和拦截（子句）”，另一个是用来”探测和试探（表达式）”。

14.2 requires 的两重身份

身份 作用 语法
子句（Clause） 限制和拦截 requires std::is_integral_v<T>

GPU组成与关键部分原理了解CUDA编程怎么可以不先了解GPU的组成和内部原理呢？了解了GPU的底层构造之后，对CUDA代码进行调优才更能得心应手。 GPU DRAM现代GPU通常使用特殊的显存颗粒：如GDDR（目前最新为GDDR7）或HBM。 GDDR相比于DDR追求低延迟，GDDR追求高吞吐量。 为什么GDDR能够实现超高带宽？GDDR的接口位宽通常比DDR宽得多。通过并行连接多个GDDR颗粒扩展数据总线宽度（参照微机原理的RAM扩展），从而形成了256bit甚至384bit的总线宽度。 除了数据总线并行扩展，每个GDDR芯片内部通常被划分为两个独立的16bit通道，这意味着可以同时处理两个不同的内存请求了。 RTX4060是GDDR6，只有128bit显存带宽，4个显存颗粒。而CPU内存双通道也可达到128bit内存带宽。主要是GDDR用了QDR（SDR是1倍，DDR是2倍，QDR是4倍），这是因为GDDR通常焊在GPU周围，走线约束什么的比较好做。但是DDR通常是DIMM的，很难约束QDR，因此基本上都是DDR。 当然，CPU目前也借鉴了GDDR的思想，PS5就把一整圈...
